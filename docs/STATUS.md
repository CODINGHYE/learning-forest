## 이번 실행 결과

OPENAI-001에서는 개인 키 연결과 PDF→OpenAI 전체 지도→개념의 뜻·용도·의미 관계→선택형 시각화 파이프라인을 적용했다. 수치 9개·Python 32개·13개 질문·4개 화면 폭·로컬 PDF와 모의 AI UI·키 수명·연결 분리·오류 검사를 통합 명령으로 확인한다. 최종 상태는 `learning-forest/qa-output/verification.json`의 상태·HEAD·입력 해시·실행 시각·검사별 결과를 따른다. 문서와 커밋 뒤 최종 입력에서 재실행하며, 과거 보고서를 현재 코드의 근거로 재사용하지 않는다.

1. 실제 교재의 표·수식·목차로 인한 개념 오탐과 누락을 평가한다.

4. 화면 읽기 도구, 키보드 이동, 실제 모바일 PDF 뷰어를 확인한다.

## OPENAI-001 반영 내용

- '내 OpenAI 연결'에서 개인 API 키·모델을 확인하고 브라우저별 서버 메모리 세션을 만든다. 연결 확인은 모델 조회이며 생성 요청이나 PDF 전송을 하지 않는다.
- 기본 분석 방식은 OpenAI다. PDF를 먼저 선택한 경우 연결 전에는 전송하지 않고, 연결 후 분석하며 취소하면 기존 지도를 유지한다. 로컬 분석은 명시적인 구조 미리보기다.
- 전체 요약·의미 관계 그림·개념별 기본 정의·용도·연결의 이유를 우선한다. 작은 관계 그림은 중심 개념의 가까운 연결 최대 4개임을 표시한다.
- 시각화는 개념 선택 시 생성하지 않는다. 지원하는 3D 예제 또는 근거 있는 관계 그림을 버튼 클릭으로 만든다. 기존 수치 예제의 설명은 시각화 아래에 분리했다.
- 원칙 0.6.0, 질문 설계서의 기본 설명·용도·12개 의미 관계 표, 코드 생성기를 함께 갱신했다.
- 키의 실제 인증·API 생성 품질·학습자 효과·배포는 확인하지 않았다. 관련 코드는 모의 API와 로컬 HTTP로 검사한다.

## DESIGN-001 반영 내용

- 왼쪽 사이드바를 상단의 학습 흐름 지도로 옮기고 아래에 독립된 질문 상세 카드를 배치했다. 작은 화면에서는 세로 지도다.
- 자체 책 길잡이 SVG, 둥근 단계, 입체감 있는 버튼을 적용했다. 흰 배경과 파랑·보라·주황의 역할을 유지한다.
- 진도는 학습자가 직접 이해 표시한 질문 수로 계산하며 해제할 수 있다. 질문을 잠그지 않는다.
- 개인 메모와 이해 표시는 PDF 내용으로 구분한 브라우저 저장 영역에 둔다. PDF 원본·본문을 브라우저 저장소에 저장하지 않는다. 저장이 막힌 경우 세션 유지와 안내를 제공한다.
- 네이버 공식 나눔스퀘어라운드 WOFF2 3굵기와 OFL을 앱에 포함했다. 질문 26~36px, 영역 19~20px, 설명 17~18px와 1.95 줄간격으로 구분한다.
- 실제 학습자 평가, 실제 유료 API 호출, 배포는 수행하지 않았다.
