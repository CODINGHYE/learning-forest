## 완료 조건

- 상위 저장소가 문서와 앱 파일을 함께 추적한다. 중첩 저장소의 메타데이터는 보존한다.
- 하네스 적용 전 코드로 돌아갈 수 있는 기준 커밋이 있다.
- 화면 설명의 수정 원본이 하나이며 생성 파일 불일치를 검사한다.
- 문서에서 PDF 로컬 분석·OpenAI 구현과 실제 검증 여부를 구분한다.
- 한 명령으로 콘텐츠·수치·Python/API·브라우저를 검사한다.
- 검증 도중 소스 변경을 감지하고, 실패 또는 생략을 통과로 보고하지 않는다.
- 유료 API 호출과 배포 없이 검증 결과·미확인 범위를 남긴다.

## 진행·결정

- Git: 상위와 내부 모두 커밋·remote 없음 확인. 내부 `.git`을 `tmp/git-metadata-backup/learning-forest.git`로 이동했다. 메타데이터를 삭제하지 않았다. 첫 커밋 `84f485b`, 브랜치 `codex/harness-management`. Git 작성자 설정이 없어 해당 명령에서만 `Codex <codex@local.invalid>`를 사용했다. 전역 설정은 변경하지 않았다.
- 복구: 현재 소스는 기준 커밋에서 조회 가능하다. 내부 Git을 꼭 복원해야 한다면 작업을 멈추고 백업 디렉터리를 원래 `learning-forest/.git` 위치로 옮길 수 있다. 복원 후에는 두 저장소가 다시 중첩되므로 개발 기준으로 쓰지 않는다.
- 원본: 화면에 쓰이던 검토된 설명을 설계서로 옮기고 `review.json`은 UI 보조 문구만 담당하도록 한다. 기존 질문 ID와 화면 설명 내용을 보존한다.
- 검증: 현재 미리보기와 분리된 로컬 서버를 실행하고 테스트 환경의 API 키는 비운다. 실제 OpenAI 호출은 이번 범위에서 제외한다.
- 병행 작업: 앱 개발 채팅이 같은 파일을 수정 중임을 확인했다. 사용자의 지시에 따라 해당 작업이 끝날 때까지 앱 소스 수정과 최종 검증·커밋은 기다리고 하네스 파일만 정리한다. 첫 빠른 검증은 생성 파일과 원본의 불일치를 감지해 `failed`로 종료했다. 검사에서 불일치를 자동 덮어쓰지 않는 동작을 확인했다.
- 병행 작업 종료 확인 후 NOVICE-001 완료본을 보존해 통합 검증을 직접 실행했다. 완료된 앱 변경과 하네스가 함께 재현되도록 최종 저장소 상태를 커밋한다. 별도 앱 기능을 추가한 것으로 보고하지 않는다.
- 오류 CM-015~017에 원본 분산·상태 불일치·병행 검증·Node 출력 집계 원인과 재발 방지 규칙을 기록했다. 수치 출력은 TAP로 고정하고 생략 및 개수 누락을 숨기지 않는다.
