# 배움의 숲 앱

PDF에서 질문 지도를 만들고 지원하는 학습 장면과 근거 페이지를 살펴보는 한국어 로컬 시제품이다. 기본 예시는 큰 질문 4개·작은 질문 13개다.

## 실행

프로젝트 루트에서 Python 의존성을 준비한 뒤 실행한다.

```powershell
python -m pip install -r requirements.txt
python learning-forest/server.py --port 4173
```

이 폴더에서 실행한다면 `python server.py --port 4173`이다. Python 실행 경로는 환경에 맞게 사용한다. `http://127.0.0.1:4173`은 이 PC에서만 접근할 수 있다.

PDF 분석은 이 서버가 필요하다. `dist/index.html`을 파일로 직접 여는 대신 위 로컬 주소를 사용한다. `python -m http.server --directory dist` 같은 정적 서버는 예시 화면만 제공하며 PDF 분석 API를 제공하지 않는다.

## 지도와 개인 학습 기록

첫 화면은 PDF 올리기·개인 OpenAI 연결 중심이다. 분석 뒤에는 데스크톱 왼쪽→오른쪽, 모바일 위→아래로 이어지는 개념지도로 이동한다. 큰 질문에서 세부 질문을 고르면 뜻·용도·연결 이유를 읽고, 필요한 경우에만 시각화를 연다. 시작 화면의 '만든 지도 이어보기'는 같은 탭의 지도를 재분석 없이 연다. 새로고침 뒤 지도 데이터는 복원하지 않는다.

이전·다음 질문 이동과 직접 이해 표시를 제공한다. 진도는 직접 이해 표시한 질문의 비율이며 객관적 평가가 아니다.

메모와 이해 표시는 PDF 내용으로 구분해 이 브라우저의 localStorage에 저장한다. 브라우저 데이터를 지우면 사라지며 다른 기기와 동기화하지 않는다. 업로드한 PDF의 원문은 저장소에 보관하지 않는다. 저장이 막히면 현재 페이지 세션 동안 유지하고 화면에서 알린다.

둥근 한글 글꼴은 로컬 `dist/fonts/`의 나눔스퀘어라운드 400·700·800이다. 출처와 OFL은 같은 폴더에 보존한다. 상세 배치는 `roadmap.css`, 시작 화면·한 방향 지도는 `journey.css`, 역할별 글자 크기·색·굵기는 `typography.css`에서 관리한다.

## 개인 OpenAI 연결과 PDF 분석

1. PDF 버튼으로 파일을 선택한다. 기본 분석 방식은 OpenAI다.
2. 연결이 없으면 '내 OpenAI 연결' 창에서 개인 API 키와 모델을 입력한다. '연결하고 선택한 PDF 분석'을 누르면 키·모델 접근을 확인한 뒤 분석한다. 연결 창을 취소하면 PDF를 전송하지 않는다. 파일보다 먼저 연결해도 된다.
3. 전체 요약·주요 개념·의미 관계를 살펴본다. 개념을 누르면 뜻·용도·연결 이유·원문 근거가 먼저 나온다.
4. 시각화가 필요하면 '3D 예시로 이해하기'를 누른다. 지원하는 예시만 그때 만들며, 다른 개념은 '연결 그림으로 이해하기'를 제공한다.

키는 서버 메모리의 브라우저별 세션에 1시간만 보관한다. 무작위 세션 쿠키는 HttpOnly·SameSite=Strict이고 키 자체를 담지 않는다. 브라우저 저장소·파일·환경 변수에 개인 키를 저장하지 않는다. 연결 해제·만료·서버 종료 시 제거되며 새로고침에서는 연결을 유지한다. 다른 브라우저의 연결과 분리한다. 이미 서버에 전송한 요청은 연결 해제 후에도 마무리될 수 있다.

연결 확인은 `GET /v1/models/{model}`로 키와 모델 접근만 확인하며 문서나 생성 요청을 보내지 않는다. 분석 모델은 구조화된 Responses 출력을 지원해야 한다. 모델 조회 권한 확인으로 생성 권한·사용 한도·설명 품질이 보장되는 것은 아니다. API 분석 요금은 키가 속한 프로젝트에 청구되고 ChatGPT 구독 요금과 별개다. 키는 앱 화면에만 입력한다.

서버 `.env`의 기본 키 연결도 유지한다. 화면에 서버 기본 연결임을 표시하며 개인 연결이 우선한다. 만료된 개인 분석 요청은 서버 기본 키로 자동 재시도하지 않는다. 이 기능은 현재 로컬 서버용이며 공개 서비스의 계정 인증·HTTPS·장기 키 보관은 구현 범위가 아니다.

## 데이터 흐름과 한계

- OpenAI 분석이 기본이다. 연결 후 선택한 PDF를 이 PC의 서버로 보내 텍스트를 추출하고 OpenAI로 전달한다. 전체 요약·개념 정의·용도·예시·의미 관계를 구조화하고 원문 인용을 실제 페이지에서 검사한다.
- '로컬 구조 미리보기'를 선택하면 AI 없이 이 PC에서 제목·지원 주제를 찾고 검토된 보충 설명을 연결한다. 의미 관계를 AI가 분석했다고 표시하지 않는다. 두 방식 모두 PDF를 디스크에 저장하지 않는다.
- 자동 하네스는 실제 키·유료 API를 사용하지 않는다. 별도 실제 검토에서 개인 gpt-4o-mini 연결과 제공된 92쪽 교재의 32개 개념 생성을 확인했다. 이는 다양한 교재 품질이나 학습 효과를 보증하지 않는다.
- AI는 번호가 붙은 실제 원문 구간을 선택하며 서버가 인용·페이지를 복원한다. 긴 지원 ML 교재는 원문에서 발견한 최대 32개 주제의 필수 응답을 검사한다. 정확히 대응하는 32개 지원 개념·16개 핵심 관계는 검토된 보충 풀이로 보강하며, AI 분석·실제 원문과 역할을 구분한다. 지원 밖 AI 초안의 의미 정확도는 별도 검토가 필요하다.
- 선택 설정은 이 폴더의 `.env.example`을 참고해 `.env`에 둔다. 키는 브라우저 코드와 Git에 넣지 않는다.
- 지원 장면만 기존 Q ID로 연결한다. 장면은 버튼 클릭 전 생성하지 않는다. 미지원 개념은 쉬운 설명·원문 근거·선택형 관계 그림을 제공한다. 임의의 3D 실험 코드를 생성하지 않는다.
- 30MB·400쪽 이하, 텍스트 추출 가능한 PDF를 대상으로 한다. 스캔 PDF에는 별도 OCR이 필요하다.
- 예시 지도 복귀 버튼으로 원래 13개 질문으로 돌아갈 수 있다. 분석 실패 시 기존 지도를 유지한다.

원본 교재와 노트북은 배포하지 않는다. 로컬 분석의 개념 연결과 설명은 보충 자료이며, 다양한 실제 교재의 추출 품질과 학습 효과는 별도 평가한다.

## 수정과 검증

- [콘텐츠 원칙](../docs/CONCEPT_MAP_PRINCIPLES.md), [질문 설계](../docs/QUESTION_SCENARIOS.md)를 먼저 읽는다.
- 제목·개념 이름·기본 설명·용도·목표·실험 설명·출처·다음 질문·의미 관계는 설계서가 원본이다. `content/review.json`은 요약·안내·범례·용어 등 UI 보조 문구만 관리한다.
- 원본 수정 후 `python learning-forest/scripts/build_content.py`를 루트에서 실행한다. `dist/content.js`만 생성 파일이며 나머지 dist 파일은 현재 직접 수정하는 소스다.
- 수치는 `dist/math.js`, Canvas 투영은 `dist/scene.js`, 화면·PDF 전환은 `dist/app.js`, 분석은 `pdf_analysis.py`와 `server.py`가 담당한다.
- 루트에서 `.\verify.ps1`로 전체 검증한다. 환경과 결과 해석은 [개발 README](../README.md), [하네스 운영](../docs/HARNESS.md)을 따른다.

3D는 Canvas에 좌표를 투영한다. PyTorch 표현은 참조 코드이며 브라우저에서 PyTorch를 실행하지 않는다.

## 현재 상태

최종 목표·완료/미완료·남은 계획은 [ROADMAP](../docs/ROADMAP.md), 기능별 확인 범위는 [STATUS](../docs/STATUS.md), 실제 교재 검토는 [REALPDF-001](../docs/plans/REALPDF-001.md), 검증 운영은 [HARNESS-001](../docs/plans/HARNESS-001.md)이 기준이다. 과거 `qa-output/report.json`은 이전 화면의 기록이다. 현재 자동 검증 근거는 `qa-output/verification.json`이다.

배포·공유 링크 생성·외부 접속 검증은 보류 중이다. 호스팅 메타데이터는 로컬 `.openai/hosting.json`에 보존하며 현재 배포 완료로 보고하지 않는다.
