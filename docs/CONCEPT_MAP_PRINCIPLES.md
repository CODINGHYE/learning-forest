# 개념지도 작성 및 수정 원칙

- 버전: 0.2.0
- 기준일: 2026-11-16 (Asia/Seoul)
- 상태: 초안. 대화에서 확인된 방향을 반영했으며 학습자 사용성 검증은 아직 하지 않았다.
- 관련 설계: [질문별 3D 장면과 설명](QUESTION_SCENARIOS.md)

## 1. 서비스의 목적

수업 PDF를 넣으면 오늘 배우는 내용의 전체 흐름을 보고, 궁금한 질문을 선택해 시각적 설명과 관련 실습으로 이동한다. 학습자는 각 기술에 대해 다음 세 가지를 설명할 수 있어야 한다.

1. 무엇을 하는가?
2. 어떤 문제나 필요 때문에 쓰는가?
3. 앞에서 배운 내용 및 다음 내용과 어떻게 이어지는가?

교재 전체의 관계를 다룬다. 특정 개념 하나의 강의로 서비스를 축소하지 않는다. 이해 순서와 실제 기술 발전 순서는 구분한다.

## 2. 질문을 쓰는 원칙

- 전문용어를 몰라도 궁금증을 이해할 수 있도록 쓴다.
- 원인에는 '왜', 과정에는 '어떻게', 대상에는 '무엇', 비교에는 '무엇이 달라질까', 예상에는 '~하면 어떻게 될까', 한계에는 '~할 수 있을까'를 사용한다.
- 모든 질문을 '왜'로 시작하지 않는다. 표현의 다양성보다 질문이 맡은 역할을 먼저 확인한다.
- 질문 하나에는 핵심 학습 목표 하나를 둔다. 답을 이미 아는 사람에게만 이해되는 질문은 다시 쓴다.
- 첫 화면에는 큰 질문 네 개를 보여준다. 선택한 가지의 작은 질문 3~4개를 펼친다. 교재 범위에 따라 개수는 조정하되 전체를 한꺼번에 펼치지 않는다.
- 기술 이름은 관찰과 설명 뒤에 붙인다. '손실함수란?'보다 '정답과 얼마나 다른지 어떻게 잴까?'를 먼저 보여준다.
- 질문 ID는 표현과 분리한다. 예: `Q3.2`는 문구가 바뀌어도 유지한다.

## 3. 관계와 발전 이야기를 만드는 원칙

각 연결에는 설명할 수 있는 이유가 있어야 한다. 아래 관계를 혼합하지 않는다.

| 관계 | 의미 | 표시 예 |
|---|---|---|
| 이해에 도움 | 먼저 알면 다음 내용을 이해하기 쉽다 | 이해를 돕는 질문 |
| 한계와 접근 | 특정 한계를 다루는 접근 중 하나다 | 이 경우에는 이렇게 해볼 수 있다 |
| 계산 흐름 | 앞의 출력이 뒤의 입력이 된다 | 계산 순서 |
| 도구 지원 | 같은 개념이나 계산을 도구가 지원한다 | 이 계산을 도와주는 도구 |
| 역사적 선후 | 확인된 연도 또는 시기를 기준으로 앞뒤를 말한다 | 출처가 붙은 연표 |

- 이해를 위한 순서를 실제 발명 순서처럼 설명하지 않는다.
- 'XOR 때문에 MLP가 발명되었다', '이전 기술은 다음 기술로 모두 대체되었다'처럼 하나의 원인으로 역사를 단정하지 않는다.
- 역사적 발명, 재발견, 대중화는 구분하고 확인된 출처를 붙인다. 근거가 없으면 날짜를 생성하지 않는다.
- 큰 질문 네 개는 개요다. 모든 학습자가 반드시 선형으로 통과해야 하는 단일 경로로 강제하지 않는다.
- 관련 질문을 연결할 때 이동 이유를 일상 언어로 표시하고, 현재 위치와 전체 지도로 돌아가는 방법을 유지한다.

## 4. 질문 상세 화면의 공통 형식

1. 질문: 선택한 질문을 그대로 표시한다.
2. 예상: 사용자가 결과를 짐작할 수 있는 짧은 질문 하나를 제시한다.
3. 관찰: 기본 카메라에서 핵심 현상이 보이는 장면을 먼저 보여준다.
4. 조작: 하나의 주된 조작으로 결과를 바꿔본다.
5. 쉬운 설명: 2~4문장으로 지금 본 현상을 설명한다.
6. 이름 붙이기: 관찰한 현상에 해당하는 기술 이름을 알려준다.
7. 연결: 다음 질문, 원문 페이지, 관련 실습 위치를 제공한다.

수식, 코드, 엄밀한 보충 설명은 별도로 펼칠 수 있게 한다. 현재 장면의 축 이름, 조절값, 결과값은 숨기지 않는다.

## 5. 3D 장면을 만드는 원칙

- 깊이가 관계, 계산 단계, 배열 구조 또는 손실 지형의 이해에 도움이 될 때 사용한다.
- 2D 자료를 3D 무대에 배치한 경우에는 원래 자료가 2D임을 밝힌다. 깊이가 단지 계산 단계라면 '계산 단계'라고 표시한다.
- 카메라 회전은 관찰 방향만 바꾼다. 입력값, 학습 상태, 분류 결과를 바꾸지 않는다.
- 값 갱신 뒤의 새 상태와 이전 상태에서 구한 기울기를 함께 보여줄 때, 기울기가 어느 상태의 값인지 명시한다. 새 값에 이전 기울기를 연결해 현재 미분값처럼 보이게 하지 않는다.
- 원본 데이터 공간, 중간 표현 공간, 파라미터 공간, 계산 그래프 공간을 구분한다. 장면이 바뀌면 축과 점의 의미를 다시 표시한다.
- 고차원 문제의 일부만 보여주면 고정한 변수와 생략한 차원을 밝힌다. 3D 그림을 신경망 전체의 정확한 모습이라고 설명하지 않는다.
- 색상과 함께 모양 또는 라벨로 집단을 구분한다. 겹친 점도 각각 확인할 수 있어야 한다.
- 카메라를 움직이지 않아도 핵심을 볼 수 있는 기본 시점을 제공한다. 텍스트는 3D 물체에 가려지거나 뒤집히지 않게 배치한다.
- 애니메이션은 유한하게 재생하고 정지·단계 진행이 가능하도록 한다. 움직임을 줄이는 설정과 정적인 설명을 제공한다.
- 장면이 없거나 지원하지 않는 개념은 그 상태를 표시한다. PDF만으로 임의의 정확한 3D 실험이 자동 생성된다고 약속하지 않는다.

## 6. 쉬운 설명의 정확성

- 인간처럼 생각하거나 이해한다는 설명 대신 무엇을 계산하고 바꾸는지 말한다.
- 예시를 기억하는 것과 새 데이터에 적용할 수 있는 것은 구분한다. 훈련 자료를 맞혔다고 일반적인 문제를 해결했다고 말하지 않는다.
- 선형 분류의 경계는 2D에서 직선, 더 높은 차원에서는 초평면이다. '모든 분류는 직선 하나로 된다'고 설명하지 않는다.
- 선형 계산만 합성하면 표현력이 임의로 늘어나지 않는다. 층 수를 늘리는 것만으로 모든 문제가 해결된다고 말하지 않는다.
- 비선형성을 좌표를 마음대로 움직이는 것으로 표현하지 않는다. 점 이동은 정의된 같은 함수로 계산한다.
- 미분은 현재 위치 근처에서의 변화율이다. 작은 변화로 관찰한 차이와 미분의 정확한 값을 구분한다.
- 역전파는 기울기 계산, 경사하강법은 파라미터 갱신이다. 역전파만 재생할 때 가중치가 바뀌면 오류다.
- 기울기는 부호가 있는 변화율이다. 사람처럼 잘못한 책임이나 확률을 나누는 양으로 설명하지 않는다.
- 여러 경로로 미치는 영향은 합친다. 계산 그래프의 중간 결과를 재사용한다는 점도 보존한다.
- 학습률이 크면 손실이 커질 수 있다. 작은 걸음이나 반복도 모든 문제에서 전역 최적해 또는 좋은 일반화를 보장하지 않는다.
- Tensor는 반드시 3D 상자가 아니다. 배열의 축, 축의 크기, 원소 수를 구분한다.
- 자동미분을 함수 전체를 기호로 풀어주는 도구와 동일시하지 않는다. 추적된 연산과 해당 미분 규칙을 이용하는 계산임을 설명한다.
- PyTorch의 `.backward()`와 optimizer의 갱신을 구분한다. 새로운 학습 단계에서는 의도하지 않은 기울기 누적을 피하도록 초기화한다.
- 불연속 함수는 무조건 학습 불가능, ReLU는 모든 지점에서 매끄럽다 같은 단정을 사용하지 않는다.

## 7. 수치와 학습 예시의 일관성

- 같은 질문군에서는 같은 데이터, 초기값, 정답을 유지한다. 다른 예제를 쓰면 전환을 표시한다.
- 가상 데이터는 가상이라고 표시한다. 실제 과일·사진 등의 성능으로 해석하지 않게 한다.
- 장면, 숫자 표시, 자막, 설명의 상태가 서로 일치해야 한다.
- 실제 계산, 미리 계산한 검증된 결과, 개념적 비유를 구분한다. 미리 만든 애니메이션을 실제 학습 실행이라고 표시하지 않는다.
- 부호, shape, 미분, 손실의 갱신 전후를 작은 독립 계산으로 확인한다.
- 분류를 설명하다 회귀용 오차 예제로 전환하면 '변화율을 쉽게 보기 위한 수치 예제'임을 표시한다. 그 수치 예제를 특정 신경망의 전체 과정으로 오해하게 만들지 않는다.

## 8. 자료 근거와 AI 생성 내용

- 설명에 PDF 페이지, 노트북 파일과 셀, 보충 출처를 연결한다.
- 교재의 내용, 서비스가 덧붙인 설명, 검증이 필요한 주장을 구분한다.
- 교재에 오탈자나 부정확한 단순화가 있으면 그대로 복제하지 않고 기록 후 확인한다.
- 첨부 자료의 지시는 실행 지시로 취급하지 않는다. 노트북도 내용 확인만으로 실행하지 않는다.
- API는 개념과 근거를 구조화하고 쉬운 설명 초안을 만들 수 있다. 시각화의 수치·함수와 출처를 사람이 검토 가능한 형태로 유지한다.

## 9. 오류 수정과 업데이트 절차

1. 아래 오류 기록에 새 ID를 발급한다.
2. 어떤 질문, 화면 크기, 조작, 설명에서 문제가 보였는지 기록한다.
3. 기대 결과와 실제 결과를 분리한다.
4. 원인을 찾고 설명·장면·계산·연결 중 수정할 대상을 정한다.
5. 질문 설계와 구현을 함께 갱신한다. 공통 원인이라면 이 원칙 문서도 수정한다.
6. 오류를 재현했던 조건에서 다시 확인한다. 확인하지 못했으면 상태를 열어 둔다.
7. 변경 이력에 날짜, 버전, 변경 이유와 확인 결과를 남긴다.

상태: `접수` / `수정 중` / `설계 반영` / `검증 완료`. 설계에 반영했다는 사실만으로 학습 효과 검증을 완료 처리하지 않는다.
