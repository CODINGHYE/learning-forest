# NOVICE-001 - 비전공자 관점 개선과 PDF 개념지도 생성

- 상태: 로컬 개선 반영 완료. 최종 소스에 대한 통합 실행 결과는 아래 보고서 기준
- 대상: 기존 질문 13개, 화면 역할·색상, PDF 분석·개념별 상세 연결.
- 관련 원칙: [작성 원칙](../CONCEPT_MAP_PRINCIPLES.md), [질문 설계](../QUESTION_SCENARIOS.md), [검토 기록](../NOVICE_REVIEW.md).
- 운영 기준: [HARNESS](../HARNESS.md). 진행 중 추가된 관리·검증 체계를 보존하고 해당 진입점으로 최종 검증한다.

## 목표와 범위

배포하지 않고 로컬에서, 사용자가 화면을 대략 보아도 버튼과 설명 영역의 목적을 알 수 있게 한다. PDF를 선택하면 본문을 분석해 새 지도를 만들고, 개념을 클릭하면 설명과 근거·지원 실험을 연다.

## 완료 조건

- 페이지와 캔버스의 흰 배경, 남색 본문·파랑 조작·주황 변화·보라 보조색을 적용한다.
- 13개 질문에 명시적인 조작 안내·범례·짧은 설명·용어 정의가 있다.
- 미분 손잡이 이름, 역전파 방향, 갱신 시점, 배열 모양의 오해를 줄인다.
- 실제 PDF의 개념 수·제목·근거 페이지에 따라 지도가 달라진다. 모르는 개념에 관련 없는 3D를 붙이지 않는다.
- 분석 중·성공·실패가 표시되고 실패 시 기존 지도를 유지한다.
- 원칙·질문 설계·검토 기록을 갱신하고 통합 검증을 실행한다.

## 진행·결정

- 배포·원격 소스 업로드·외부 접속 검증을 하지 않는다.
- 키 없이 동작하는 로컬 구조 분석을 기본으로 한다. OpenAI 문맥 분석은 별도 명시적 선택이며 키가 없으면 비활성화한다.
- OpenAI 요청은 공식 Responses API의 구조화 출력으로 준비하고, 인용 구절·페이지·장면 ID를 다시 검증한다. 실제 호출은 하지 않는다.
- 설명 원본은 질문 설계서의 문단이다. UI 요약·범례·조작 안내는 review.json으로 구분한다.
- 업로드 PDF를 로컬 디스크에 저장하지 않는다. 텍스트 추출 범위와 3D 지원 범위를 명시한다.
- 통합 실행에서 자동 재생 종료 뒤 버튼의 활성 상태 오류(CM-014)를 발견해 수정했다.
- 기존 하네스 작업이 병행된 상태를 보존한다. 검증 도중 하네스 입력이 변경된 실행은 최종 통과로 사용하지 않고 안정된 입력에서 다시 실행한다.

## 결과

- 설계·구현: 적용. 상세는 검토 기록 참조.
- 자동 검증: `verify.ps1`로 콘텐츠 계약·구문·수치 9개·Python 경계 24개·질문 13개 및 화면 너비 4종을 확인한다. 최종 변경 후 보고서는 `learning-forest/qa-output/verification.json`으로 갱신한다. 실제 OpenAI 호출은 하지 않는다.
- 화면 확인: 에이전트가 흰 테마의 데스크톱·모바일·PDF 화면을 캡처해 검토했다. 실제 학습자 참여 확인은 아니다.
- 학습자 검증·실제 API·배포: 미실시.
